# 常見問題

## 新增紀錄後多久會生效？

我們的資料庫是「期望狀態」，背景程式會把它同步到 DNS 服務（Lazco DNS）。DNS 服務每天能接受的變更批次有限，系統會把一段時間內的變更合併成一批送出：閒置時幾秒內完成，最慢大約 18 分鐘，`[ PENDING ]` 旁邊會顯示預計生效的時間，完成後變成 `[ SYNCED ✓ ]`。之後各家 DNS resolver 的快取更新時間取決於 TTL，「自動」大約是 5 分鐘。同一個名稱、同一種類型的多筆紀錄會共用一個 TTL（取最小值）。

## 怎麼自己檢查？

```
dig +short www.你.dev-in.tw CNAME @1.1.1.1
dig +short 你.dev-in.tw A @101.101.101.101
```

`101.101.101.101` 是 TWNIC 的 Quad101。在 DNS 編輯器裡，每筆紀錄右側都有「複製 dig 指令」的按鈕。

## 為什麼不能填 10.x 或 192.168.x？

A／AAAA 只接受公網位址。私有位址外部連不到，還可能被拿來做 DNS rebinding 攻擊內網，所以一律擋下。

## 為什麼 CNAME 不能和其他紀錄同名？

這是 DNS 標準（RFC 1034）的規定：一個名稱有 CNAME，就不能再有 A、MX、TXT 等紀錄。一鍵設定在套用前會列出哪些紀錄會被一起刪除。

## HTTPS 憑證呢？

由你指向的平台簽發（GitHub Pages、Vercel、Netlify、Cloudflare Pages 都會自動處理）。我們不代管憑證，也不開放橘雲代理。

## 可以有幾個名字？

每人 2 個子網域，每個子網域 10 筆紀錄。整個 zone 的紀錄總數有上限，名額滿了會暫停申請。

## 為什麼我的申請要審核？

GitHub 帳號建立未滿 30 天，或名稱和知名品牌（例如銀行、電商）很像，會先由人看一眼，避免被拿來釣魚。一般在一天內完成。

## 不用了怎麼辦？

到子網域「設定」的危險區釋出。紀錄會立刻撤下，名稱進入 30 天冷卻期。也可以轉移給另一位 Dev-in.tw 使用者。

## 發現有人拿 dev-in.tw 做壞事？

請到[檢舉頁](/report)，或寫信到 abuse@dev-in.tw。
